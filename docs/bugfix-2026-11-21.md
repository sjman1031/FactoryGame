## 3. 수정 내역

### P0

#### S3 · 이름이 바뀐 직렬화 필드를 기존 에셋에서도 읽게 함
- `ResourceNodeData.nodeId`에 `[FormerlySerializedAs("nodeID")]`, `RecipeData.craftTime`에 `[FormerlySerializedAs("craftingTime")]`을 붙였습니다.
- **이유:** 노드 에셋 5개와 레시피 에셋 12개가 이전 이름으로 저장돼 있습니다. 이대로 열면 노드 id가 비어서 채굴이 전혀 되지 않고, 제작 시간이 전부 4초로 돌아갑니다. 전체 임포트로도 고쳐지지만, 이 속성이 있으면 임포트하기 전에도 값이 유지됩니다.

#### B1 · 인벤토리를 슬롯 모델로 (`Core/Inventory.cs`)
- 이전에는 `stackSize`를 아이템 **종류별 총량 한도**로 써서, 20칸 창고도 철광석을 100개까지만 받았습니다.
- 이제 아이템은 `stackSize`개마다 한 칸을 차지합니다(올림 나눗셈). `GetAddableAmount(item)` = (빈 칸 + 이 아이템의 칸) × stackSize − 현재 보유량.
- 보유량은 계속 종류별 총량으로 들고 있으므로 **저장 형식은 바뀌지 않습니다.**
- **연쇄 수정 (제작기):** 이 변경 때문에 제작기 입력 버퍼(8칸)를 재료 하나가 다 채워서, 다른 재료가 못 들어와 제작이 멈출 수 있게 됩니다. 그래서 `ManufacturerBuilding.TryInputItem`이 재료마다 한 스택까지만 받게 했습니다. 이전 동작과 같은 한도입니다.
- **테스트:** 20칸 × 100 = 2000개, 혼합 적재(철 150 = 2칸 → 석탄 900 가능), 경계값(null·0·음수), 레시피 소모 등 19개가 모두 통과했습니다.

#### B3 · world.bin을 tmp에 쓰고 성공해야 커밋 (`SaveSystem.cs`, `WorldPreGenerator.cs`)
- 이제 `world.bin.tmp`에 씁니다. `FinalizeWorldWrite`가 인덱스를 다 채우고 나서야 `world.bin`으로 이름을 바꿉니다. `Exists()`는 `world.bin`만 보므로, 쓰다 만 파일은 "저장 있음"이 되지 않습니다.
- `WriteChunk`/`Finalize`는 bool을 돌려주던 것을 **예외를 던지게** 바꿨습니다. `GenerateAll`의 catch에서 `AbortWorldWrite()`(파일 닫기 + tmp 삭제)를 호출합니다. 기록된 청크 수가 총수와 다르면 커밋하지 않습니다.
- 생성 도중 오브젝트가 파괴되면(플레이 종료, 씬 전환) `destroyCancellationToken`으로 멈추고 Abort합니다. `OnDestroy`에서도 Abort해서 파일 핸들이 남지 않게 했습니다.
- 읽을 때 길이가 0인 인덱스 엔트리는 건너뛰고, 엔트리 수가 헤더와 다르면 열지 않습니다. 이전 형식이나 반쯤 쓴 파일을 이중으로 막는 장치입니다.
- **W12 같이 해결:** 같은 슬롯의 world.bin을 읽는 중이면 쓰기 전에 먼저 닫습니다.
- 새 월드를 커밋하기 전에 이전 게임의 `live.json`·`.bak`을 지웁니다. 그래서 커밋 도중 앱이 꺼져도 이전 게임의 건물이 새 지형에 섞이지 않습니다(남는 `.tmp`의 시작 위치로 복구됩니다).

#### B2 · 불러오기 실패가 영구 손실로 굳지 않게 (`SaveSystem.cs`, `SaveController.cs`, `LiveData.cs`, 각 건물)
1. **손상 파일 백업:** `live.json`을 읽지 못하면 `live.json.corrupt-<시각>`으로 복사합니다.
2. **자동 저장 차단:** 저장 파일이 있었는데 하나도 읽지 못하면 `SaveSystem.LoadFailed = true`가 됩니다. 이때 `OnApplicationQuit` 자동 저장을 막습니다. F5 수동 저장은 경고를 남긴 뒤 허용하고, 저장에 성공하면 플래그를 내립니다.
3. **모르는 데이터 보존:** 복원하지 못한 항목을 버리지 않고 들고 있다가 다음 저장에 그대로 다시 씁니다.
   - 아이템(플레이어·창고): 새 `InventorySaveUtil.Restore/Write`를 둘이 함께 씁니다. id를 못 찾은 항목과, 자리가 없어 못 넣은 나머지를 보관합니다.
   - 건물: 카탈로그에 프리팹이 없는 건물은 `BuildingRegistry._unresolved`에 원본 그대로 보관합니다. 카탈로그가 연결되지 않았으면 전부 보관합니다.
   - 제작기: 못 찾은 `recipeId`를 보관합니다.

#### B4 · live.json 원자적 교체와 복구 순서 (`SaveSystem.cs`)
- 이전의 `Delete → Move`를 `File.Replace(tmp, final, final.bak)`으로 바꿨습니다. 파일이 없을 때는 `Move`를 씁니다.
- 불러올 때 `live.json → live.json.tmp → live.json.bak` 순서로, 처음으로 정상 파싱되는 파일을 씁니다.
- 셋 다 없으면 `(0,0,0)` 구석이 아니라 **맵 중앙 청크의 한가운데**(평지 존)에 스폰합니다. 위치는 world.bin 인덱스 범위로 계산하므로, world.bin 형식(v2)은 바꾸지 않았습니다.

### P2

- `BuildingRegistry`, `SaveSystem`, `LoadingContext`, `ChunkGenerator`에 `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` 초기화를 붙였습니다. `GameDatabase`와 같은 방식입니다.

#### W9 · V1 — 청크 읽기 (`SaveSystem.cs`, `ChunkData.cs`)
- `ReadSingle` 4096번 → `Stream.Read` 한 번 + `Buffer.BlockCopy`. 읽기 버퍼는 재사용합니다. 청크 길이도 검증합니다.
- `ChunkData`에 `(coord, heights)` 생성자를 추가해 배열을 두 번 할당하지 않게 했습니다. 쓰이지 않던 `buildings` 필드는 지웠습니다(건물 B안).

#### S7 · 마주 보는 벨트 (`ConveyorBelt.cs`)
- 앞 칸 벨트가 나를 향하면(`Dot < -0.5`) 출력 대상으로 잡지 않습니다.

#### K7 · 플레이어 해제 (`PlayerController.cs`, `PlayerMovementManager.cs`)
- `Register(null)` 대신 `Unregister(this)`를 씁니다. 등록된 본인일 때만 해제합니다. `?.`가 Unity의 파괴 검사를 건너뛰는 문제도 `== null`로 바꿨습니다.

#### 그 밖의 방어 코드
- `BuildingCatalog`: 항목의 `buildingId`가 비어 있으면 프리팹의 클래스 이름을 씁니다. 이전에는 빈 칸 하나가 Awake에서 `ArgumentNullException`을 냈습니다. 중복이면 경고하고, `Get(null)`은 null을 돌려줍니다.
- `SaveController`: `_player`가 연결되지 않았으면 에러 로그를 남깁니다.
